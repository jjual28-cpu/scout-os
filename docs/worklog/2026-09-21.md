# 2026-09-21 작업기록 — 인스타 연결 복구 (apex/www 호스트 불일치 해결)

집PC. 비즈니스 인증 통과(9/17) 후, 인스타 연결이 계속 실패해서 잡음.

## 증상
- 설정 → 인스타그램 연결 클릭 → `?instagram=fail`. Vercel 런타임 로그에 `[instagram] callback failed`
  **로그가 안 남음** = 콜백의 catch 이전, **조용히 튕기는 경로**(state/세션 쿠키 불일치)로 실패.

## 진짜 원인 — apex/www 호스트 불일치
- 인스타 승인 URL의 `redirect_uri` = `https://scout-os.kr/api/instagram/callback` (**apex 고정**,
  NEXT_PUBLIC_APP_URL=apex).
- 사용자가 **www.scout-os.kr**에서 시작하면: authorize가 www에서 실행 → state·세션 쿠키가 **www**에 묶임 →
  콜백은 **apex**로 옴 → apex에서 www 쿠키를 못 읽음 → state 불일치/getUser null → 조용히 `back('fail')`.
- **왜 이제서야?** 비즈니스 인증 때 apex를 www 리다이렉트에서 **직접 서빙**으로 바꿔서(9/16), 사용자가 apex에
  머물 수 있게 됨. 예전엔 apex→www 리다이렉트라 항상 www였고 쿠키가 일관됐음. (jdiel도 그때 연결됨)
- 확인: 인스타 consent 화면 URL에 redirect_uri=scout-os.kr(apex)인데 사용자는 www에서 시작 → 불일치.

## 수정
1. `services/instagram/origin.ts` (신규) `appOrigin(request)`: 요청 호스트(허용목록 scout-os.kr·www.scout-os.kr)를
   그대로 origin으로. authorize·callback이 이걸 써서 시작·콜백·복귀 URL을 같은 호스트로 정렬. (커밋 5df3628)
2. `lib/supabase/middleware.ts`: **www.scout-os.kr → scout-os.kr 308 정규화**(페이지 라우트만, `/api/*` 제외 —
   Meta 웹훅·데이터삭제 콜백 보존). 사용자가 www로 들어와도 apex로 넘어가 흐름이 한 호스트로 정렬됨. (커밋 baea77e)
