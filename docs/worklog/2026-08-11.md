## 검색이 계속 "중단"되던 버그 2종 (근본 해결)
프로덕션에서 검색이 계속 "중단"됨. Apify 콘솔 확인 결과 **실행은 성공(3분 소요)·크레딧 넉넉($0.85/$29)** — 엔진 문제 아님. 원인은 앱 쪽 2가지였음:
- **① 유령 running 캠페인** (`d3f02d8`): 스크래핑 3분 도는 중 브라우저 닫으면 캠페인이 'running'으로 영구정지 → 같은 검색어 재검색이 그 유령을 재활용·복원 즉시 취소 + one-running 락으로 새 검색 차단. → 검색 시작 시 STALE_RUNNING_MS(10분) 넘은 running 자동 실패처리 + findRunning 신선도 필터.
- **② 클라이언트 자동중단 타이머** (`4fd71b2`→`a5e03fb`): 화면에 캐시된 옛 캠페인의 startedAt이 남아, 새 검색을 시작하자마자 "10분 초과"로 오판→1초 만에 자동취소. startedAt 리셋으론 부족(브라우저 캐시가 옛 JS 물고 있었음)해서 **결국 클라 자동중단(give-up) 타이머를 통째로 제거**. 서버(status 라우트 STALE_MS)+글로벌 폴러가 오래 멈춘 검색을 처리하므로 클라 타이머 불필요. **→ 해결됨(사용자 확인: 더는 중단 안 남).**
- 교훈: 클라이언트 수정은 브라우저 **하드 새로고침(Ctrl+Shift+R)** 필요. 배포 라이브 여부는 `npx vercel ls scout-os`로 확인.
