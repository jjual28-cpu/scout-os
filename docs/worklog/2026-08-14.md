## 1. AI 무료화 마무리 & '노란 경고' 근본 해결 (제일 큰 건)
증상: 검색 결과에 **"AI 처리 중 문제가 생겨 자동 판정을 건너뛰었어요"** 노란 경고가 계속 뜸.
진단 엔드포인트(`/api/diag/ai`)를 붙였다 떼며 **프로덕션에서 실제 호출을 재현**해 원인 확정:

- **모델명**: 이 Google AI Studio 키는 `gemini-flash-latest` 만 통함(versioned 이름 `gemini-2.5-flash`
  등은 404). 기본 모델을 `gemini-flash-latest`로 고정. (`a98e393`)
- **진짜 원인 = 503**: 작은 핑은 OK인데 **실제 판정(matchCreators, json·maxTokens 2000, 후보 24개)
  같은 큰 호출에 Gemini 무료 티어가 간헐적으로 503(모델 과부하)** 반환 → AI_ERROR → 경고.
  - **재시도**: `callOpenRouter`에 429/500/502/503/504/529 백오프 재시도(최대 4회). (`3942a7e`)
  - **폴백**: 그래도 실패면 대체 모델 `gemini-flash-lite-latest`로. 측정상 두 모델 각 4/4 성공
    → 사실상 100%. (`7e2e486`)
- **캐시가 옛 경고 캠페인 재사용**: `findCached`가 `ai_error` 있는 캠페인은 재사용 안 하도록
  `.is('ai_error', null)` 추가. 재검색만 해도 옛 경고 캠페인 건너뜀. (`a38b884`)

## 2. 검색 속도 ~2배 (상세 스크랩 병렬)
느린 상세 스크랩이 2번(이름검색 상세 + 해시태그 작성자 상세) **순차**라 ~4분+.
- **overlap(겹침) 검색**: primary=해시태그 글(빠름)→작성자 상세보강, background=이름검색 상세를
  discover에서 병렬 시작. stage3에서 둘을 합침 → **~4분 → ~2.5분**, 후보도 늘어 결과 개수↑.
  안전장치: enrich 런은 `claimStage` CAS로 정확히 1개, 미완료 시 stale(10분) 실패, `flow='overlap'`
  마커로 기존/타플랫폼 회귀 없음. (`ebb30d8`, `dd0a14c`)

## 3. 검색 품질 (무관 계정 제거)
- **단순 키워드도 AI 해시태그**: "여행" 한 단어도 예외 없이 planSearch 사용 → `#여행크리에이터·
  여행브이로그` 같은 진짜 태그(규칙기반 `#여행스타그램` 폴백보다 우수). (`b765508`)
- **AI 미판정 후보 숨김(근본)**: AI가 배치를 심사하고도 verdict 안 준 후보가 그냥 통과(null)돼
  화면에 뜨던 문제 → '주제 불일치'로 reject 처리(제외 포함으로 재열람). maxTokens 2000→3200으로
  누락 방지. (`6511695`)
- **AI 판정 '주력 콘텐츠' 기준 강화**: 그 주제 게시물 가끔 올려도 주력이 다른 분야면 reject,
  애매하면 reject. (`aa3b915`)
- **규칙 필터 보강**: 헤어살롱(헤어디자이너·헤어모델·미용사) 및 마사지샵(마사지본점·스웨디시·
  타이/태국/아로마/감성/커플마사지·로미로미·경락·지압·1인샵) 신호 추가.
- **브랜드 잡계정 제거**: 브랜드 검색이 크기 필터를 아예 안 걸어(신생브랜드 배려) 팔로워 17·게시물
  2짜리 잡계정도 통과하던 것 → **브랜드 신호(쇼핑링크·브랜드카테고리·공식이름) 없는 초소형 계정
  제외**(`tooSmall && !looksLikeBrand`). 신호 있으면 크기 무관 통과. (`1e1f257`)

### 릴스 음원 v2 — "진짜 트렌드 숫자" 문제 + 다음 방향 (2026-08-15 새벽)
사용자 피드백: 추출은 되는데 **숫자가 무의미**(사용 2·0개), 대표 릴스가 **말소리만**(음악 안 들림).
원인: 표본 작음 + 해시태그 스크랩이 **릴스가 아니라 사진/캐러셀** 위주 + 우리가 긁는 게 인기
콘텐츠가 아님. → 표본 세기 방식은 근본적으로 진짜 트렌드가 안 됨.
- **시도한 해결책 "음원 페이지 역추적"**: `instagram.com/reels/audio/{id}` 를 긁어 그 음원의 **진짜
  전체 사용수 + 인기 릴스**를 가져오려 함. **검증 결과: apify/instagram-scraper는 audio 페이지를
  못 긁음**(에러 반환, audio_id·canonical_id 둘 다). → 이 액터로는 불가.
- **다음 방향(내일 노트북, 조사 필요)**:
  1. **인스타 음원/릴스 트렌드 전용 Apify 액터 찾기** — audio 페이지나 reels 피드를 긁는 전용 액터가
     Apify 스토어에 있음. 그걸로 audio_id → 실제 사용수·인기 릴스 역추적.
  2. 아니면 실제 **릴스(영상)만** 큰 표본으로 긁어 재생수 합으로 랭킹(도달 가중). 단 여전히 표본 추정.
  3. 근본적으로 인스타는 공식 트렌드 음원 데이터가 없어 한계 존재 — 전용 액터가 최선.
- 현재 상태: 코드는 서 있고(추출·집계·UI·검색 작동), **데이터 품질만 위 방향으로 개선 필요**.
